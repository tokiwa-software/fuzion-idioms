Idiom # 190: Call an external C function

See programming-idioms.org:

Code

A feature declared with => native has no Fuzion implementation. Instead, it says to compiler: "that function exists, but it's written in C; look for it by name", here foo. We can also see that the return type of foo is unit (which is similar to void in C). Also the Fuzion types map to C types: i32 to int, unit to void and mutate.array f64 to double *.

Since the C prototype takes a non-const pointer, foo may modify the array. Mutable data in Fuzion is bound to a mutate effect, which is instated by mutate ! ()-> ... .

The Makefile compiles foo.c into a static library libfoo.a Then, fz -c compiles the example via the C backend with three options:-CInclude adds the foo prototype, -CLink links the libfoo.a, and -CFlags tells the C compiler to look for them in the current directory. Finally, the program runs.

To try it yourself, clone the fuzion-idioms repository and run make in src/idiom190. The sample implementation of foo prints the array like this:
